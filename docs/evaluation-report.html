Routing Arabic government documents to the right institution

A classifier that reads incoming Arabic correspondence and decides which of 14 Saudi government bodies should handle it — with the measurement methodology that says whether it can be trusted.

The headline number is the unflattering subset, not the flattering one. Both classifiers score far higher on an easy generator — the baseline gets 100% — but that measures a model against its own phrasebook. The number worth acting on is what each does on documents built to be hard, and the gap between them there is the finding: +20.3 points, nearly double the gain on ordinary documents.

The language model run is partial. The free tier's daily token cap was exhausted at 65 of 86 documents, so the gpt-oss figures rest on 59 scored documents (31 hard), and the 21 missing are the tail of the corpus rather than a random sample. Treat them as a strong signal, not a settled measurement. The baseline figures are complete.

The constraint that shaped everything

This system routes incoming citizen correspondence. That data is operational and cannot be published, no public dataset carries destination-institution labels, and one that did would be a breach rather than a resource. So the test set was built, not borrowed.

86 Arabic documents across all 14 institutions, written as real correspondence rather than assembled from keyword pools — 26 easy, 16 medium, 44 hard. Sixteen of those are adversarial cases placed on the exact boundaries the taxonomy declares: two per confusion pair, one in each direction.

Here is one, labelled GOSI (social insurance), not labour:

أصبت أثناء عملي لدى منشأة مقاولات… سجلت المنشأة الإصابة وانتهى العلاج بتقرير طبي نهائي.
لا خلاف بيني وبين صاحب العمل على الأجر أو العقد، وما زلت على رأس العمل لديه.
طلبي منحصر في إحالتي إلى اللجنة الطبية لتقدير نسبة العجز وصرف التعويض.

Every surface signal says labour dispute — employer, contract, workplace injury. The bolded sentence flips it: there is no dispute with the employer, so this is a disability assessment, which belongs to GOSI. A keyword model routes it wrongly. That is what the 63.6% is measuring.

Why the hard subset gains twice as much

Ordinary documents: +11.3 points. Hard subset: +20.3.

TF-IDF cannot represent negation. In the boundary case quoted above, the sentence that decides the answer is a denial — there is no dispute with the employer — and a bag of character n-grams sees only the employer vocabulary surrounding it, weighted heavily. The routing decision lives in a clause-level relation the model has no way to encode.

A transformer attends across the sentence and can represent "not X, but Y". The adversarial subset is precisely where that capability pays, and the measured gap is the evidence that fine-tuning an Arabic encoder is worth its cost rather than an assumption that it would be.

Why accuracy is not the metric that matters

Sending a document to the wrong ministry costs far more than holding it for a clerk to look at. So the system reports accuracy over the documents it routed automatically, separately from overall accuracy, and the cut-off between them is chosen by measurement.

Target mode: the lowest cut-off meeting a 95% accuracy bar, so coverage is as high as the bar allows.

Two guards that changed the conclusions

Both of these found something. Neither would have been noticed by looking at accuracy alone.

Calibration, checked before thresholding

A threshold on a confidence score means nothing unless the score tracks reality. ECE 0.337 — the baseline is badly under-confident: it says 0.47 and is right 80% of the time. That is exactly the state in which a sensible-looking cut-off silently holds half the archive for no gain, and it is why the shipped default was wrong.

Held-out validation of the cut-off itself

Choosing a threshold on the same documents you measure it on flatters the result. Picking on one half and testing on the other gives +11.5% optimism — the sweep's own recommendation over-promised by that much on documents it had not seen.

Design decisions

The choices a reviewer would want justified.

The taxonomy is configuration, not code

One YAML file defines the institutions, their scope, and the tie-breaking rules between confusable pairs. Prompts, labels, test data and metrics all derive from it, so adding an institution is an edit to data — nothing downstream hardcodes an id.

Output is constrained to the institution list

The destination is a JSON-schema enum of real ids, so the model cannot invent one. Against a self-hosted gateway that may not enforce schemas, the id is validated locally anyway — an invented destination fails loudly rather than routing a document nowhere.

Identifiers are masked before anything leaves the process

National IDs, phones, IBANs, tax numbers and emails become typed placeholders — [رقم ضريبي] still signals "this mentions a tax number", which is what routes it, while the identifying value is gone. Measured cost: 37 identifiers masked, accuracy 80.2% → 80.2%.

The labelling queue has two lanes

A queue ranked by difficulty is a biased sample, so agreement measured on it understates real accuracy. A parallel uniform-random lane is the only honest estimate, and its documents are served blind — the model's guess is stripped server-side, so a reviewer cannot be anchored by it.

Backends are swappable by design

A registry behind structural Protocol contracts: a self-hosted gateway, the Claude API, and an offline baseline all satisfy one narrow interface. Batching is a separate protocol, so the baseline is not made to grow stub methods for an API it has no notion of. Defaults keep every document on the network; choosing a cloud path prints exactly what leaves.

Engineering

  • 214 tests, 87% coverage, all offline — no test can reach the network, and CI sets the API key to empty so one that tries fails loudly.
  • CI on every push: ruff, ruff format, mypy, and the full suite across Python 3.11/3.12/3.13 on both Ubuntu and Windows, plus a smoke job that drives the whole offline pipeline and a job that fails if a credential or a real document is ever committed.
  • A full end-to-end sweep from a clean clone found six defects that unit tests, lint and types had all passed — including a raw SDK traceback on a missing key, and an evaluator that silently scored only the overlap when pointed at the wrong prediction file.

What this cannot tell you

Stated first rather than buried, because these matter more than any figure above.

The taxonomy is unreviewed by a domain expert

The 14 institutions and their boundary rules are a careful reconstruction, not confirmed practice. If they are wrong, every number here is wrong with them. A 20-minute Arabic review sheet exists to settle it, including whether ministry-level routing is even actionable and whether one destination per document is the right model at all.

No real document has been processed

Every figure above, from either classifier, is measured on documents this project wrote. They were authored to be adversarial rather than convenient, which makes them a fair discrimination test — but a discrimination test is not a measurement of production accuracy, and nothing here forecasts what happens on correspondence a ministry actually receives.

The language model run is partial, and it ran off-network

59 of 86 documents, cut short by a free-tier daily token cap. The missing 21 are the tail of the corpus, not a random sample, so the true figure could move in either direction.

It also ran against a public endpoint rather than the self-hosted gateway the deployment policy requires. That is defensible only because the corpus is entirely synthetic — no real citizen data exists in it. The gateway itself remains unreached, so the model that will actually serve production has still never been measured.

Two built improvements are unmeasured

A confusion-pair tiebreak — a focused two-way second pass when the top two institutions form a declared pair, which is where every error in both runs falls — is implemented and covered by tests, but has never run against a live model. A compact prompt that cuts token cost 27% is in the same position. Both are plausible improvements with no evidence behind them yet.

OCR is verified only on clean input

Tesseract reads rendered Arabic at 29/29 words exact. That is a ceiling, not a forecast — stamped, faxed and skewed paper is a different problem and remains unmeasured.

What would change the picture

  • Fifty real documents, sampled as a contiguous slice rather than hand-picked, would turn every figure here from a discrimination test into a measurement.
  • One domain conversation would confirm or correct the taxonomy, and answer the multi-label and granularity questions before they become expensive.
  • Gateway access would move the measurement onto the model that will actually serve production, and onto the network policy the deployment requires.
  • One more day of quota completes the remaining 21 documents and settles whether the tiebreak and the compact prompt earn their place — both are built, tested and unproven.
